# Деплой тестового стенда

Стенд живёт на общем VPS, где кроме него крутятся чужие контейнеры и системный
nginx на 80/443. Отсюда почти все правила ниже: ресурсы делятся с соседями, и
трогать общее нельзя.

## Куда деплоим

| Что | Значение |
|---|---|
| Хост | `deploy@2.59.161.124` (ключ на рабочей машине, `ssh -o BatchMode=yes` проходит) |
| Каталог | `~/apps/niaz` |
| Compose-файл | `docker-compose.vps.yml` |
| Контейнер | `niaz-app`, слушает `127.0.0.1:3010` |
| Наружу | системный nginx, конфиг `/etc/nginx/sites-available/niaz` |
| Домен стенда | `niaz-test.ru`, `SITE_INDEXABLE=false` |

## Порядок

```bash
ssh deploy@2.59.161.124
cd ~/apps/niaz
git pull --ff-only origin main
: > build.log
nohup docker compose -f docker-compose.vps.yml build >> build.log 2>&1 &
# дождаться конца сборки, затем:
docker compose -f docker-compose.vps.yml up -d
docker image prune -f
docker builder prune -af      # только после подъёма контейнера
```

## Правила

**Код едет через `git pull`, а не через SCP.** Репозиторий
`github.com/Artamonych/niaz` публичный, на сервере он склонирован по HTTPS, и
`git fetch` работает без учётных данных. Это отличие от OkaCRM на том же VPS:
там репозиторий приватный и файлы возят по SCP.

**Только `git pull --ff-only`.** На сервере рядом с рабочей копией лежат
`build.log` и `deploy.log` — неотслеживаемые файлы. `git reset --hard`
их не тронет, но привыкать к нему не стоит: он молча выбрасывает любую правку,
сделанную на сервере по горячим следам. `--ff-only` в такой ситуации честно
падает и даёт разобраться.

**Сборку запускать в фоне с логом.** На VPS 1,9 ГБ памяти на все проекты, и
`next build` идёт несколько минут. Синхронный `docker compose build` по SSH
успевает упереться в таймаут клиента, а прерванная сессия оставляет сборку
в непонятном состоянии. Поэтому `nohup ... &` и хвост `build.log`.

**Порядок контейнеров задан в compose и его не обходить.** Сначала отрабатывает
и завершается `migrate` (миграции Prisma и первичное наполнение), и только
после его успеха стартует `app`. Поднимать `app` отдельно — значит однажды
получить приложение на несуществующей схеме.

**Кэш сборки чистить ПОСЛЕ деплоя, а не перед.** Он разрастается примерно
до 6 ГБ и съедает весь запас, но `docker builder prune -af` перед сборкой
лишает её кэшированных слоёв — она уходит выкачивать пакеты заново и упирается
во всё то же зеркало. Порядок такой: собрали, подняли, потом
`docker image prune -f` и `docker builder prune -af`. Тогда к следующему
деплою есть и место, и свободный старт.

**Перед сборкой смотреть `df -h /`.** Диск всего 15 ГБ, образы лежат в
`/var/lib/containerd` (docker здесь на overlayfs-снапшоттере, не в
`/var/lib/docker`), и один только `niaz-migrate` весит 1,75 ГБ. Деплой
10.09.2026 упёрся в `no space left on device`. Запас меньше 2 ГБ — сначала
чистить, потом собирать.

**Сборка могла дойти до конца, даже если compose отчитался об ошибке.** В том
же случае оба образа собрались, а место кончилось на записи служебного
`metadataFile` в `/tmp`. Прежде чем пересобирать с нуля, сравнить
`docker images` с образом работающего контейнера
(`docker inspect niaz-app --format '{{.Image}}'`): если тег `niaz-app:latest`
уже указывает на свежий образ, достаточно `up -d` без `--build`.

**Зеркало Alpine в `Dockerfile` — Яндекс, и это не вкусовщина.** С этого VPS
`dl-cdn.alpinelinux.org` (Fastly) стабильно виснет на выкачке крупных пакетов:
соединение открыто, данные не идут, `apk add` стоит с нулевой загрузкой
процессора сколько угодно. Мелкие запросы к тому же хосту при этом проходят
за 0,7 с, поэтому со стороны похоже на «сборка просто долгая». Проверено
10.09.2026: через `mirror.yandex.ru/mirrors/alpine` та же установка
`python3 make g++` заканчивается за 49 секунд, через dl-cdn — три зависания
подряд. dl-cdn оставлен запасным вариантом, оба вызова обёрнуты в `timeout`,
чтобы сборка падала, а не висела.

**Не трогать чужое на этом сервере.** `docker system prune` и
`docker volume prune` снесут образы и тома соседних проектов. Чистить только
`docker image prune -f` — он убирает лишь висячие слои. Том `db` с базой
CRM не удалять никогда: там заявки с сайта.

**Секреты живут на сервере.** `~/apps/niaz/.env` в git не попадает и при
деплое не перезаписывается: там `AUTH_SECRET`, пароль администратора CRM и
адрес стенда. Если файл потерян — учётку админа придётся заводить заново
через `migrate`.

**`SITE_INDEXABLE` на стенде — всегда не `true`.** Иначе `robots.txt`
откроется, и тестовый домен встанет в индекс рядом с боевым сайтом, растащив
по дублям тот самый SEO-актив, ради сохранения которого делается переезд.

**`NEXT_PUBLIC_SITE_URL` — переменная времени сборки.** Она вшивается в бандл
и в `canonical`, поэтому меняется только пересборкой образа, а не
перезапуском контейнера.

## Проверка после деплоя

```bash
docker ps --format '{{.Names}}\t{{.Status}}'
curl -sI https://niaz-test.ru | head -3
curl -s https://niaz-test.ru/robots.txt | head -3   # на стенде должно быть Disallow: /
```

В браузере открывать с Ctrl+F5: nginx отдаёт статику Next.js с длинным
кэшем, и без сброса можно час смотреть на старую вёрстку и считать, что
деплой не доехал.
